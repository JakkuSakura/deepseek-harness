# Agent Note：模型可见的上下文用量

Status: implemented

[English](2026-10-19-model-visible-context-usage.md) | 中文

## 问题

长会话中的模型无法观测自己的上下文预算。当目标轮次或压缩检查点让剩余工作显得庞大时，`deepseek-flash` 会从自己的叙述中推断出「上下文耗尽」，在窗口大部分空闲时收窄或停下手上的工作：在一次记录的会话中，它在 1,000,000 token 窗口的 252,175 处声称「上下文所剩无几」（[讨论 #6736](https://github.com/deepseek-ai/deepseek-harness/discussions/6736) 报告了同样的行为，当时占用为 51%）。该提示词中唯一像预算的数字是目标轮次的 `Round: N/M`；另一处上下文稀缺文本是压缩检查点，而它描述的是过去的缩减，不是当前占用。

## 决定

`@deepseek-ai/dsh-token-meter` 通过可选的 `ctx.systemPrompt` 服务注册一个运行时上下文小节 `token:usage`，使用新分配的 `CONTEXT_USAGE` 顺序值 100，排在 sandbox 与审批策略之前。该小节渲染一句话，读取语义由[占用笔记](2026-07-29-projected-token-usage-and-request-context.zh.md)所有的 `contextPressure` 投影：该投影的 `projectedTokens`（缺失时回退到 `pressureTokens`）对比其 `contextWindow`，例如「Context usage: about 250,000 of the 1,000,000-token context window is in use (25%, about 750,000 tokens free).」

上报值按窗口的 5% 取整，任何非零用量至少上报一档，因此会话只在占用跨档时追加一条取代旧快照的快照。只有在既有提供方样本又有已声明窗口时该小节才渲染，无 agent 的装配不贡献任何内容。循环仅在该快照文本变化时才把它落成持久 user 消息，这正是该句子可从会话日志重建的原因。

## 上报契约

模型与会话状态显示读取同一个投影，因此在 GUI 中看到 25% 占用的用户，会在提示词中看到同一个数字。该句子不决定压缩何时运行：压缩仍读取 `measure()`；由于投影独立地把最新用量样本与最新声明的窗口配对，切换模型后百分比可能滞后一次请求。

## 考虑过的替代方案

- **上报压缩阈值而不是窗口。** 否决：阈值属于可能未挂载的压缩后端，meter 会因此承担不归它所有的策略。窗口由适配器声明，在任何声明它的路由上都有意义。
- **每一步上报精确 token 数。** 否决：运行时上下文快照是仅追加的，精确数字会每一步追加一条消息并累积被取代的快照。
- **保持 meter 对模型不可见，由压缩渲染该句子。** 否决：压缩是可选组件，其 pre-step 测量在提示词装配之后运行，而这些断言在第一次压缩发生之前就已出现。

## 后果

meter 在挂载提示词注册表时会贡献模型可见内容；测量仍可用于没有提示词注册表的组合。该数字是粗粒度参考：它经过取整、不是阈值，靠近档位边界的上报值可能与精确占用相差最多半档。在既有窗口又有用量时，快照会多出一条运行时上下文消息；事件类型、线格式字段与配置都没有变化。
